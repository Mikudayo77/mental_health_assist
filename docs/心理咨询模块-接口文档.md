# 心理咨询模块接口文档（Apifox 使用版）

适用代码：当前工作区未提交的「套餐 / 预约 / 订单 / 模拟支付 / 退款 / 人工咨询 / 危机干预 / 通知」模块。

- 服务地址：`http://localhost:1236`
- 配套导入文件：`docs/counseling-openapi.json`（OpenAPI 3.0，可直接导入 Apifox）
- 鉴权方式：登录后拿到 JWT，放在**请求头 `token`** 中（不是 `Authorization`）

---

## 一、Apifox 五步接入

### 1. 导入接口

Apifox → 打开项目 →「项目设置」→「导入数据」→ 选择 **OpenAPI/Swagger** → 选择 `docs/counseling-openapi.json` → 导入。
导入后会自动生成所有接口、请求参数和请求体示例。

### 2. 创建环境

「环境管理」→ 新建环境 `本地`：

| 变量名 | 值 |
|---|---|
| `baseUrl` | `http://localhost:1236` |
| `token` | 先留空 |

把接口的前置 URL 设为 `{{baseUrl}}`（导入的 OpenAPI 已写入 `http://localhost:1236`，也可以直接使用）。

### 3. 全局配置 token 请求头

「项目设置」→「环境」→ 在 `本地` 环境添加公共 Header：

```
token: {{token}}
```

这样除注册/登录外的接口都会自动带上 token。

### 4. 登录并自动写入 token

打开 `POST /api/user/login`，请求体：

```json
{
  "username": "smoke_user",
  "password": "password123"
}
```

在该接口的「后置操作」中新增「提取变量」：

- 变量名：`token`
- JSONPath：`$.data.token`
- 保存到：环境变量 → `本地`

之后每次执行登录，环境里的 `token` 会自动刷新，其他接口直接复用。

### 5. 准备三种角色的账号

角色编码：`1` 普通用户、`2` 管理员、`3` 咨询师。**角色写在 JWT 里，角色变更后必须重新登录换 token**。

| 角色 | 准备方式 |
|---|---|
| 普通用户 | 直接调 `POST /api/user/add` 注册，密码登录 |
| 管理员 | 先注册普通账号，再执行 SQL 提升，然后**重新登录**：<br>`UPDATE user SET user_type = 2 WHERE username = '你的账号';` |
| 咨询师 | 注册普通账号 → 用该账号调 `POST /api/counselor/apply` → 管理员审核通过 → **重新登录**（审核会自动把 `user_type` 改为 3） |

建议在 Apifox 建三个环境（`本地-用户`、`本地-管理员`、`本地-咨询师`），各自保存一份 token，切换环境即可切换角色。

## 二、通用约定

### 2.1 统一响应结构

所有接口 HTTP 200 时返回：

```json
{
  "code": "200",
  "msg": "操作成功",
  "data": {}
}
```

| 场景 | HTTP 状态 | 响应体 |
|---|---|---|
| 成功 | 200 | `{"code":"200","msg":"操作成功","data":...}` |
| 业务异常（如状态不允许、时段冲突） | **200** | `{"code":"BUSINESS_ERROR","msg":"具体原因","data":null}` |
| 参数校验失败 | **200** | `{"code":"400","msg":"参数错误","data":"字段错误摘要"}` |
| 未登录 / token 失效 | **401** | `{"code":"A0301","msg":"访问未授权","data":null}` |
| 角色无权限（`@PreAuthorize`） | **403** | 空响应体 |

> 注意：业务异常仍是 HTTP 200，Apifox 里不能只看状态码，要断言 `code == "200"`。

### 2.2 分页响应

```json
{
  "total": 12,
  "records": []
}
```

分页参数统一为 `page`（从 1 开始）、`size`。

### 2.3 数据格式

- 时间：`LocalDateTime`，格式 `2026-10-23T15:00:00`，**不带时区后缀**
- 金额：JSON 数字，保留两位小数，如 `199.00`
- 枚举：响应中除 `status` 数值外，另有 `xxxDesc` 中文描述字段可直接展示

## 三、完整业务流（按顺序执行）

以下是一条可直接在 Apifox 跑通的主流程，括号内为执行角色。

| 步骤 | 接口 | 说明 |
|---|---|---|
| 1 | `POST /api/user/add` ×3 | 注册：普通用户、咨询师、管理员三个账号 |
| 2 | SQL 提升管理员 | `UPDATE user SET user_type=2 WHERE username='admin账号';` |
| 3 | `POST /api/user/login` ×3 | 分别登录，各环境保存 token |
| 4 | `POST /api/counselor/apply`（咨询师） | 提交资质申请 |
| 5 | `GET /api/counselor/page`（管理员） | 查看待审列表，拿到 `counselorId` |
| 6 | `POST /api/counselor/audit`（管理员） | `auditStatus=1` 通过；咨询师**重新登录** |
| 7 | `POST /api/package/create`（管理员） | 建套餐；也可直接用种子套餐 id 1/2/3 |
| 8 | `GET /api/package/list`（用户） | 查询上架套餐 |
| 9 | `GET /api/counselor/list`（用户） | 查询可预约咨询师，拿到 `id` |
| 10 | `POST /api/appointment/create`（用户） | 创建预约，返回 `orderNo` |
| 11 | `POST /api/payment/mock-pay`（用户） | 模拟支付，返回支付记录 |
| 12 | `GET /api/appointment/counselor`（咨询师） | 查看待确认预约，拿到预约 `id` |
| 13 | `POST /api/appointment/{id}/confirm`（咨询师） | 确认预约 |
| 14 | `POST /api/counseling-chat/send`（双方） | 文字咨询 |
| 15 | `GET /api/counseling-chat/messages`（双方） | 轮询拉取新消息 |
| 16 | `POST /api/appointment/{id}/complete`（咨询师） | 咨询完成（必须在预约开始时间之后） |
| 17 | `GET /api/refund/preview/{orderId}`（用户） | 查看可退金额 |
| 18 | `POST /api/refund/apply`（用户） | 提交退款申请 |
| 19 | `GET /api/refund/page`（管理员） | 查看待审退款 |
| 20 | `POST /api/refund/audit`（管理员） | 审核通过/拒绝 |

### 关键请求体示例

**创建预约**（`appointmentStart` 必须是未来时间，且不能与该咨询师已有 `待确认/已确认` 预约重叠）：

```json
{
  "counselorId": 1,
  "packageId": 2,
  "appointmentStart": "2026-10-23T15:00:00"
}
```

响应：

```json
{
  "code": "200",
  "msg": "操作成功",
  "data": {
    "orderNo": "CO202610222105478680556",
    "appointmentNo": "AP202610222105478616713",
    "amount": 199.00
  }
}
```

**模拟支付**：

```json
{ "orderNo": "CO202610222105478680556" }
```

**人工咨询发消息**：

```json
{ "appointmentId": 1, "content": "最近总是失眠，很焦虑" }
```

**退款审核**：

```json
{ "refundId": 1, "approve": true }
```

拒绝时：`{ "refundId": 1, "approve": false, "rejectReason": "不符合退款条件" }`

### 4.2 AI 心理聊天（原有接口）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/psychological-chat/session/start` | 登录 | 创建 AI 会话 |
| POST | `/api/psychological-chat/stream` | 登录 | SSE 流式对话 |

创会话请求体：`{"sessionTitle":"标题可选","initialMessage":"初始消息"}`，返回 `data.sessionId`（形如 `session_31`）。

流式请求体：

```json
{ "sessionId": "session_31", "userMessage": "我最近压力很大" }
```

SSE 输出（`Content-Type: text/event-stream`）：

```
event:message
data:{"code":"200","msg":"操作成功","data":{"content":"我","type":"normal"}}

event:message
data:{"code":"200","msg":"操作成功","data":{"content":"理解...","type":"crisis"}}

event:done
data:{}
```

- `type=normal`：模型正常输出
- `type=crisis`：命中高危危机，内容为求助热线文案（可能出现在首帧）
- 以 `event:done` 结束

> Apifox 新版本可在响应区切换「SSE/流式」查看；若被缓冲或显示不全，用 Apifox 的「复制为 cURL」到终端执行，或用 Postman 的 SSE 视图。

### 4.7 退款

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/refund/preview/{orderId}` | 普通用户 | 退款预览：是否可退、金额、规则说明 |
| POST | `/api/refund/apply` | 普通用户 | 提交退款申请 |
| GET | `/api/refund/mine` | 普通用户 | 我的退款记录 |
| GET | `/api/refund/page` | 管理员 | 全部退款，参数 `page`、`size`、`status` |
| POST | `/api/refund/audit` | 管理员 | 审核退款 |

退款预览响应示例：

```json
{
  "code": "200",
  "msg": "操作成功",
  "data": {
    "refundable": true,
    "refundAmount": 99.50,
    "ruleDesc": "距预约开始2~24小时，退款50%",
    "rejectReason": null
  }
}
```

**固定退款规则**（以申请/审核时的当前时间为基准）：

| 条件 | 结果 |
|---|---|
| 咨询师尚未确认（预约待确认） | 全额退款 |
| 已确认，距开始 > 24 小时 | 全额退款 |
| 已确认，距开始 2 ~ 24 小时 | 退 50% |
| 已确认，距开始 < 2 小时 | 不可退 |
| 已完成 / 已取消 / 已拒绝 | 不可退 |

管理员审核通过时会按审核时刻重新计算金额；此时已不满足条件的申请会被自动拒绝。

### 4.8 人工咨询聊天

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/counseling-chat/send` | 用户/咨询师 | 发送消息 |
| GET | `/api/counseling-chat/messages` | 用户/咨询师 | 增量拉取消息 |

拉取参数：`appointmentId`（必填）、`afterId`（上次拉到的最大消息 id，首次传 0）、`limit`（默认 100，服务端限制 1~200）。

**使用方式（轮询）**：前端每 2~3 秒调用一次 `messages?appointmentId=1&afterId=上次最大id`，把返回的记录追加到会话中；没有新消息时返回空数组。

**发言时间窗**：
- 预约状态必须是「已确认」
- 当前时间在 `[预约开始 - 15 分钟, 预约结束 + 30 分钟]` 内
- 咨询完成后只读，不能再发消息

发送者类型由服务端根据登录身份判定（`senderType`：1 用户 / 2 咨询师），不要在前端传。

### 4.9 危机干预

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/crisis/page` | 管理员 | 危机记录分页，参数 `page`、`size`、`riskLevel`（LOW/MEDIUM/HIGH）、`handleStatus`（0待处理/1已处理） |
| GET | `/api/crisis/{id}` | 管理员 | 危机记录详情 |
| POST | `/api/crisis/{id}/handle` | 管理员 | 标记处理 |

处理请求体：


触发方式：AI 聊天或人工聊天中命中敏感词（自杀、自残、跳楼、遗书等）后，系统会调用大模型评级；风险为 HIGH 时通知全部管理员，AI 聊天还会在流中推送 `type:"crisis"` 的热线片段。人工聊天的消息会带 `crisisFlag=1`。

## 六、常见问题

**Q1：调接口返回 403 且响应体为空？**
当前账号角色不匹配。确认登录返回的 `roleType`，咨询师/管理员需先完成审核或 SQL 提升，然后**重新登录**。旧 token 里的角色不会自动更新。

**Q2：返回 401 `访问未授权`？**
请求头 `token` 未传、写错或已过期（默认 24 小时）。重新登录并在 Apifox 环境里刷新 `token`。

**Q3：业务错误但 HTTP 状态是 200？**
本项目约定：业务异常用响应体 `code=BUSINESS_ERROR` 表达，参数错误 `code=400`。断言请写 `$.code == "200"`。

**Q4：创建预约提示「该时段咨询师已有预约」？**
同一咨询师「待确认/已确认」的预约时段不能重叠。换一个时间，或先把旧预约取消/拒绝。

**Q5：创建预约提示「预约时间必须在未来」？**
`appointmentStart` 必须是当前时间之后，且格式为 `yyyy-MM-ddTHH:mm:ss`（不带时区）。

**Q6：人工聊天提示「预约未确认或已结束」/「不在咨询时间窗内」？**
仅「已确认」预约、且在预约开始前 15 分钟到结束后 30 分钟之间可发言。测试时可先把预约时间改到临近，或让咨询师确认后调整系统时间对应的预约时间。

**Q7：退款预览显示不可退？**
按固定规则计算：距开始不足 2 小时、已开始、已完成、已取消、已拒绝均不可退。查看 `rejectReason` 了解具体原因。

**Q8：模拟支付一直成功，怎么测失败？**
把 `application.yml` 中 `payment.mock.fail-rate` 改为 `1` 并重启；测试完改回 `0`。

**Q9：Apifox 看不到 SSE 流？**
SSE 是 POST + 自定义 Header，浏览器原生 EventSource 不支持。Apifox 请用「SSE/流式」视图或复制为 cURL；前端请用 `fetch` 流式读取或 `@microsoft/fetch-event-source`。
